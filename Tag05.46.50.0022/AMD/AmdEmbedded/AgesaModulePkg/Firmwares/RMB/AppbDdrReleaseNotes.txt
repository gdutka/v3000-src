Notes
-----

   The enhancements listed below therefore also apply to release F-2023.06

------------

     for every trained rank (specified in CSR VrefDACSelCtrl)
 - Initial DDR5 PHY VrefDAC setting specified in 'PhyVref' message block field is unchanged:
   Receiver Vref = VDDQ*PhyVref[6:0]/128

Enhancements
------------
Training Firmware:
 - PMU Revision: 0x0016
 - DDR4: When HdtCtrl <= 4, report in the log all the MRS commands, except for those used to sweep
         the values for a trained MR/RCW/BCW; only report the final trained value. If required, all
         MRS commands can be reported when HdtCtrl is set to 3 or less for debug purpose.
 - DDR4/DDR5: Reduce size of string files by removing those related with level below 4
 - DDR5: Avoid resetting PllLockPhSel (keep the value as-is)
 - DDR5: (RDIMM/LRDIMM) New option Reserved7D2[0], when set to 1, a modified MemReset sequence is
         used during DevInit to work around RDIMM reset issues observed with some RCD parts
 - DDR5: Disable RTT_NOM_* during DQ swizzle discovery
 - DDR5: New option Reserved7D2[1], when set to 1, update RTT_PARK to value Reserved7D2[4:2]
         during PDA enumeration
 - DDR5: Cover full range of TAP4 coefficient values during wr2D DFE
 - DDR5: Remove dummy read before starting RxEn training
 - DDR5: Skip ECC bytes during x16 byte swap detection step (ECC bytes cannot be swapped)
 - DDR5: Update setting of DfeCtrl during rd2D DFE training (applies to PHY with 4-TAP DFE variant)
 - DDR5: Demote to level 4 the debug messages related with MRW/MPC/VrefCS/VrefCA commands (was level 5)
 - DDR5: Add new option D5Misc[7], when set to 1, at the end of MRL training, the trained values for
         both channels will be set to the same value, corresponding to the maximum between both channels
 - DDR5: Improve execution speed of data acquisition step during wr2D training using first a
         coarse search approach to extract tighter range limits for both Vref and Delay dimensions
 - DDR5: New option Reserved7D0[1:0] to improve execution speed of wr2D DFE; when this field is
         set to a value K > 0, wr2D DFE will iterate up to K times, starting with bias-step mode up to
         K larger than the one requested in TX2D_DFE_Misc[3:2] in order to extract a tighter range of
         coefficients used to limit the search at the next iteration (similar to a zoom-in approach)
 - DDR5: Update the existing Rx/Tx eye filtering mechanism based on Reserved1E5 and Reserved1E6 to be
         independent per direction (see details in respective message block comments)
 - DDR5: Add new option Reserved7D0[2], when set to 1, extend by 16x the bit sequence length
         configured for the data acquisition step during wr2D training
 - DDR5: Add new experimental option Reserved7D0[7:6], Reserved7D0[5:4], Reserved7D1[7:6] and
         Reserved7D1[5:4] to configure the weight function used during the optimization of
         VrefDQ (MR10), TxDqDly, VrefDAC, and RxClkDly, respectively. The supported values are:
           0 => width*width (i.e., legacy mode, no change)
           1 => width
           2 => square_root(width)
           3 => cube_root(width)
 - DDR5: Add new option D5Misc[5], when set to 1, read training will be executed again after
         write training, but this time using the PRBS23 pattern since writes are now trained;
         in such case, if rd2D DFE option is also enabled, it is not executed during the first
         iteration of read training (before write training), unless ReservedF6[4] is set to 1
 - DDR5: Some message block comment updates
 - DDR5: New option ReservedF6[6] to set individual (per DRAM) RTT CK/CS/CA during DevInit before DRAM
         CS/CA training; when this option is set to 1, the message block fields MR32R*Nib*, resp.
         MR3R*Nib*, are used as inputs to provide the RTT CK/CS (resp. CA) values, per DRAM, using
         same format as used in MR32 (resp. MR33); note that MR3*Nib* message block fields were
         already existing but were only used as outputs, hence they are now used as input using
         MR33 format for RTT CA, but only for this new option. As usual, in case of DDIMM, only
         the value for even ranks are significant, yet it remains recommended as for any other
         setting to set to the same value the corresponding fields of the corresponding odd rank.
 - DDR5: When reporting in the log all the MRW/MPC/VrefCS/VrefCA commands (new feature introduced in
         2023.01 release), avoid reporting the MRW used to sweep the values for a trained MR/RW;
         only report the final trained values, otherwise this may create a log too large (all the MRW
         can still be reported when HdtCtrl is set to 3 or less for debug purpose if required).
 - DDR5: (RDIMM/LRDIMM) PhyCfg[1:0] is now used to control setup/hold time of QCA during QCS/QCA training
         in SDR mode; the control is similar to how it is already supported in DDR5 UDIMM
         case for CA training in 2N mode:
           PhyCfg[1:0] 2N/SDR mode CA setup/hold time setting w.r.t. CK capturing CS assertion at
                       DRAM interface (This setting is only applicable if D5Misc[6] is set to 1, and
                       in case of RDIMM/LRDIMM if SequenceCtrl[14] is set to 1)
           00 = 2UI setup time, 2UI hold time (Recommended: CK rising edge center in CA eye)
           01 = 3UI setup time, 1UI hold time (CK/CS/CA timing similar with RCD SDR1 mode)
           10 = 1UI setup time, 3UI hold time (CK/CS/CA timing similar with RCD SDR2 mode)
           11 = Reserved
 - DDR5: Support CA swizzle for older PUB versions using D5Misc[3]:
           Backward compatibility option only for PUB versions not supporting CSR field PhyConfigCX;
           must be set to 1 if and only if the value of DWC_DDRPHY_CAXBAR is defined in the RTL and
           PhyConfigCX is not supported (must be 0 otherwise)
 - DDR5: (RDIMM) Improve 2D CA eye contour display in the log for SDR mode
 - DDR5: (UDIMM) Improve reported VrefCS margins following 2D CS training
 - DDR5: (RDIMM/LRDIMM) Improve reported VrefCA margins following RCD CA DFE training
 - DDR5: (RDIMM/LRDIMM) Remove CATrainOpt[6] introduced in 2023.01, because this option is useless;
         users can set any QCK delay using message block fields associated with the RW that control
         QCK delays.
 - DDR5: (RDIMM/LRDIMM) Extend QCA training delay range by one tCK in case of SDR1 mode to cover
         the case where the right edge of the eye was missed


Limitations
-----------
 - DDR5: Post optimization of RxClkC and the option to avoid VrefDAC training counters during rd2D cannot be both enabled
         if rd2D DFE is disabled. That is, setting ReservedF6[3:0] to a non-zero value, while setting ReservedF6[5] to 1
         and RX2D_TrainOpt[0] to 0 will result in a training failure.

    sensitive if the external WL delay is such that the DQS is aligned with internal WL pulse

  * Added more traces in external WL: dump TxDqs delays before adjustment

    training errors in the message block output field Reserved1E3 (per channel, per DIMM).
    if Reserved1E3 is not 0 after training, at least one error was detected:
      Reserved1E3[0] == 1: Error during CS training Dimm 0 Chan A
      Reserved1E3[1] == 1: Error during CS training Dimm 1 Chan A
      Reserved1E3[2] == 1: Error during CA training Dimm 0 Chan A
      Reserved1E3[3] == 1: Error during CA training Dimm 1 Chan A
      Reserved1E3[4] == 1: Error during CS training Dimm 0 Chan B
      Reserved1E3[5] == 1: Error during CS training Dimm 1 Chan B
      Reserved1E3[6] == 1: Error during CA training Dimm 0 Chan B
      Reserved1E3[7] == 1: Error during CA training Dimm 1 Chan B
  * QCS and QCA margins are now extracted and stored into the new message block output
    fields QCS_Dly_Margins_* ad QCA_Dly_Margin_*.
 - New DDR5 options controlled by message block field Reserved1E4:
  * Reserved1E4[0]: Enables the "legacy mode" for DRAM PDA enumeration. Instead of sending a continuous
    sequence of DQS toggles to enumerate each device, one after the other, a single BL16 DQS sequence
    is sent during the short tPDA_DQS_delay window after the MPC enumerate ID command
  * Reserved1E4[1]: Dumps MR after read/write training stages (only if HdtCtrl < 5)
  * Reserved1E4[2]: Avoids sanitizing in devinit the specified message block values for
    MR37, MR38 and MR39 (i.e., customer provided values are used during training)
  * Reserved1E4[3]: Sanitize MR2[7] to 0 during devinit, since it will be set only when and after
    internal WL is executed
  * Reserved1E4[4]: Forces DCA+PAR signals at 1 during initialisation phase,
    before sending the first commands
 - DDR5 RDIMM/LRDIMM: Applying the RCW05 and RCW06 "_next" value settings when multi-context
   feature is used
 - DDR5 RDIMM/LRDIMM: SMBus request messages now include a field for the RW page number,
   using bits [15:8] of the 32-bit payload.
 - DDR5: Doubled the wait time between the long NOP and the REF command during the DRAM
   Self-Refresh Exit sequence

   after devinit (RCD CA passthrough mode is no more required to be set for MPC)

 - Fix a bug in WL when RxEn is skipped (Channel B was not trained)
   * Note: skipping RxEn is an option not officially supported but bug is fixed anyway

 - Update WL final TxDqsDly setting position when internal WL is skipped
   Now, with WL_ADJ set to 0, WL_pulse raising edge is set 0.5 UI (resp. 1.5 UI)
   before first DQS raising edge of 2tCK (resp. 3tCK and 4 tCK) write preamble;
   WL_ADJ remains a sign magnitude 8bit value to increase/decrease the TxDqsDly
   by a value in the range [-127, +127] fine step (inversion is no more applied
   on the provided value);
   * Note: Skipping Internal WL remains an option not officially supported, but
           we update the trained value positioning to be consistent between
           different write preamble configuration (it was not the case before, since
           in case of 2tCK, the WL_pulse was in front of DQS of first data beat,
           while it was in front of first DQS of preamble in the two other cases).

 - Force OP[7] to 1 in VrefCS command (no more relying on MR12[7] setting,
   to be compliant with future JEDEC)

 - Rename the following unused MR fields in DDR5 message block (ORG is for Other Rtt Group):
   MR9_*  into MR32_ORG_*_next (MR32 next value for Other Rtt Group)
   MR23_* into MR111_*         (Need explicitly disable DFE for low frequency)
   MR36_* into MR32_ORG_*      (MR32 value for Other Rtt Group)
   MR40_* into MR33_ORG_*      (MR33 value for Other Rtt Group)
   MR48_* into MR33_ORG_*_next (MR33 next value for Other Rtt Group)

 - Other fields update in message block (mainly DDR5)
   - DDR5 Reserved1A is replaced by RXEN_ADJ (not yet supported)
   - DDR5 Reserved20 is replaced by MRE_MIN_PULSE (not yet supported)
   - DDR5 Reserved21 is replaced by DWL_MIN_PULSE (not yet supported
   - Add DDR5 LRDIMM training stage control in SequenceCtrl (not yet supported)
   - Shared2DVrefResults is now reserved (not required in DDR5, no more required in DDR4)
   - New DDR5 field ResultAddrOffset (to report results at end of training)
   - New DDR5 fields BCW04_next and BCW05_next (context switch for LRDIMM)
   - New DDR5 MR3R*Nib* fields (to report MR3 trained values)
   - New DDR5 VrefCSR*Nib* fields (to support VrefCS setting per device)
   - New DDR5 VrefCAR*Nib* fields (to support VrefCA setting per device)

 - Add new options enable with AdvTrainOpt
   AdvTrainOpt[0]: Use same data sequence on all DQ during read training (MRR31 based)
     0x0 : Use different data sequence per DQ of a nibble
           (2 or 4 different sequences, depending on D5Misc[4])
     0x1 : Use same data sequence for all DQ of a nibble
   AdvTrainOpt[2:1]: DQ odd seed setting during read training
     (MRR31 based, don't care if either AdvTrainOpt[0] or D5Misc[4] is 1)
     0x00: one bit shift  w.r.t. DQ even seed
     0x01: two bit shift  w.r.t. DQ even seed
     0x10: RFU, must be 0
     0x11: RFU, must be 0
   AdvTrainOpt[4:3]: Extended sequence for read training (w.r.t. AdvTrainOpt[7] setting)
     0x00: 1x burst length
     0x01: 2x burst length
     0x10: 4x burst length
     0x11: 8x burst length
   AdvTrainOpt[6:5]: Extended sequence for write training (w.r.t. AdvTrainOpt[7] setting)
     0x00: 1x burst length
     0x01: 2x burst length
     0x10: 4x burst length
     0x11: 8x burst length

 - Add new feature, enable via PhyCfg[5], to permit setting, via PDA, different VrefCS and
   VrefCA for each DRAM, using the new message block fields VrefCSR*Nib* and VrefCAR*Nib*.
   Since this setting is done before CS/CA training, PDA enumeration is now executed
   earlier during devinit

 - Add new feature, enable via PhyCfg[3], to detect DQ swizzle automatically
   If PhyCfg[4] is also set, this feature also assume the CSR DqLnSel* are
   already set and error is reported if values do not match

 - Extend DDR5 internal WL to populate the MR3R*Nib* fields

 - Use 2x larger delay step size during first pass of rd2D training to extend range
   to find left-edge of the eyes (enhancement to support larger DQS->DQ skew)

 - Dump trained VrefDAC* values after rd2D (if HdtCtrl < 5)

 - Extend DDR4/DDR5 DM training FW to support up to +/- one UI of board delay skew
   between DQ and DM

 - Extend end of training to write back in DCCM at ResultAddrOffset the trained values
   that are not reported in message block; for now, only the wr2D DFE value are written
   back (see training FW application note for detail)
   * Note: the now obsolete data dump mailbox feature will be removed in a future release

 - Add new stage completion major mailbox messages for LRDIMM (DDR4/DDR5)
   (see training FW application note for detail)
   * NOTE: this is impacting DDR4 LRDIMM

 - Setting CSR Seq0BGPR3 before end of training, as required for fast PLL relock

 - Update DDR5 MRR support for x16 device

Limitations
-----------
 - DDR5 rd2D/wr2D DFE option is available only for pstate 0
 - RCW trained value resulting of DDR5 RCD QCS/QCA training are not reported back
   in message block (RCD RCW needs to be read by host to retrieve the values)

Known Issues
------------
 - DDR4 RDIMM: Spurious MCLK start-stop is generated at beginning of training,
   even when skip Memory reset option is enable

Version A/B/C/D/E-2020.08
September 15, 2020

Changes from version A-2020.02-BETA
(mandatory)

Bug Fixes
---------
 - DDR5: Add MR14, MR15, MR51 and MR52 in the set of MR to write during devinit
   and at the end of training;
 - DDR5: toggle PAR during PDA enumerate in 2N/SDR mode;
 - Some update of DDR5 training FW to avoid X-propagation that can
   occur with 4bit ECC configuration;
 - DDR5 RFM command was wrongly used instead of refresh all command;
 - Support enabling DDR5 RCD parity check at the end of training
  (RCW01[0] can be set to 1);
 - Fix DM training in case of DDR5 UDIMM 2N mode and DDR5 RDIMM SDR mode;
 - DDR5 RDIMM: Fix (RCD) QCS/QCA training;
 - DDR5: Fix internal ACSM delay to consider 2N mode setting and RCD RCW11 value (for RDIMM);

Enhancements
------------
Training Firmware:
 - PMU Revision : 0x0003
 - DDR5 training FW aligned with DRAM JEDEC Rev 0.99 and RCD01 JEDEC REv 0.9 Draft 2;
   Backward compatibility for older JEDEC version is no more supported,
   D5Misc[7] and D5Misc[3] are now reserved;
 - Add option PhyCfg[2] to provide channel ID in DDR5 RDIMM SMBus related
   mailbox message for non-global RCW update (see DDR5 training FW app note);
 - Improved support of DDR5 UDIMM 2N mode and DDR5 RDIMM SDR mode;
 - DDR5: Send VrefCS command during devinit, just after VrefCA command;
 - DDR5: Support enabling DRAM CRC check at the end of training (including 4bit ECC case
   in which upper nibble write CRC will be disable in DRAM associated with ECC);
 - DDR5 RDIMM: Avoid sending mailbox SMBus command for non-populated RDIMM;
 - DDR5: Avoid writing MR34 and MR35 at the end of training;
 - DDR5: Use MR32[6] user value from message block to set only groupB or groupA (but not both)
   for RTT CK/CS/CA termination using values provided in MR32 and MR33 (other group disable);
 - DDR5: D5Misc[1] is now reserved, internal WL setting is now controlled only with MR2[7];
 - DDR5: New mailbox major message to dump trained DRAM DFE values (see DDR5 training FW app note);
 - DDR5: Support 4TAP DFE training;
 - DDR5: Support Self-Refresh Entry with Frequency change, and RCD multi-context setting;
 - DDR5: Read/Write 1D no more implemented as in DDR4, but instead using 2D implementation
   where Vref are not swept; RdDeskew bit in sequenceCtrl is now reserved, since
   RdDeskew always executed during read 1D/2D training for pstate 0; wrDq1D high-effort
   option no more supported since not required;
 - DDR5: Report trained Read/Write 2D Vref/Delay margin in message block
   see new fields [RxClkDly|VrefDac|TxDqDly|DeviceVref]_Margin*);
 - DDR4: Support CA training;

Limitations
-----------
 - DDR5 Support Self-Refresh Entry with Frequency change, and RCD multi-context setting was
   not verified;
 - DDR5 RDIMM: QCS/QCA training may not work in SDR mode (but should not be required);
 - DDR5: 4TAP DFE training is not complete and not validated;
 - DDR5: Vref/Delay margin for trained CS/CA is not reported
   (the new message block output fields [CS|CA]_[Dly|Vref]_Margin_* are always 0);

Known Issues
------------
 - Fast PLL relock is not yet supported
 - DDR4 RDIMM/LRDIMM: Spurious MCLK start-stop is generated at beginning of training,
   even when skip Memory reset option is enable

Minimum Required Versions
-------------------------
- PUB: 4.00
- Phyinit: E-2020.08
