AIM-T 1.0 Release Notes
Release date: December 12, 2023



NOTE: The signed binaries of AIM-T is for Production platform. It has below updates 
1) Source code security audit/recommendtaion completed
2) MPM-FW memory region protected through FMR
3) Address Space Layout Randomization for tasks is implemented
4) Only HTTPs support is enabled 
5) KVM traffic is encrypted
6) WPA3 (SAE/Enterprise) & 6GHz are not supported
7) SSC bit to be enabled in BIOS for G3 state to work for AIM-T
8) Cloud Manageability feature is not supported
9) For Provisioning the target, AMD Provisioning Console 1.0.0.244 to be used
10) Text Redirection feature is not supported for AIM-T 1.0

System requirements:

AIM-T Hardware: 
* Mayan or Lilac AMD CRB platform equivalent platform
* Rembrandt (RMB) secure silicon (B0/B1) PRO
* QCOM WLAN (Hastings Prime)

AIM-T Software:
* MPM FW - v28.28.03.A7
* AMS - v3.0.0.666

Dependency:
ASP Version  : 00.28.00.6F

Remote Console:
* Windows 10/11
* DASH CLI v5.0.0.1757 (Release version )
* AMD Provisioning Console v1.0.0.244 (obtain this from OEM Collaborate portal)
	NOTE: oT or oMT configuration package generated by AMD Provisioning Console should be used only in Trusted environment

Quick steps:
1. Prepare BIOS with MPM FW, PSP, AGESA. Refer AIM-T Integration Guide for detailed information.
2. Flash this BIOS on the AIM-T platform and enable Manageability options in BIOS Set up screen.
3. Boot to Windows and install AMS
4. On Remote Console, generate provisioning package using AMD Provisioning Console.
5. On the AIM-T platform, run the provisioning application.
6. AIM-T system is ready and can be managed remotely from DASH CLI, AMC or any other DASH supported Management Console.
7. oT and oMT (Trusted) packages should always be privsioned in Trusted environemnt
8. Make sure to generate KVM key during provisoning

Known issues (in this release):

*[SWCM-1579] MPM is automatically waking up from sleep in x86NRC mode when connected to WPA2 Enterprise
*[SWCM-793]TOTP token is not changing when MPM is getting into a sleep state
*[SWCM-347]In S5 state, Software Inventory profile provides only BIOS version details
*BIOS mode KVM performance is good, OS mode KVM performance may have latency and in few systems (~1/10), we noticed "startoskvm" command is failing or exiting without graceful closure.
*If any ungraceful exit of vnc-viewer, wait for 3 min and if the system is still not manageable then reboot the system
*In some Wired Network configurations, viewer might face intermittent disconnections
*AIM-T supports DASH-CTS currently on OS mode only.
*To end the KVM session,the KVM viewer must be closed.In case Windows OS is shut down without closing the KVM Viewer, the system will enter into KVM mode the next time when it is powered on.
*[SWCM-1256] Ctrl + Alt + Del button in KVM viewer may not function as expected in certain Windows build during OSKVM


Troubleshooting:
* If DASH is not responding in Windows, try to restart the AMS service in Service Manager. If that does not work, then reboot the system.
* After DASH power shutdown, if the platform is unresponsive, then manually power down and power on the platform.
